# 产品规则配置

## 配置界面和计算契约

财务进入产品规则后先选产品与规则适用范围。固定账期可按业务场景及生效时间匹配。实战班从已同步期次选择单期配置，也可设置从哪一期起沿用。同一份规则版本里维护多条分润分项，每条都能回答以下问题。

| 字段 | 配置内容 |
| --- | --- |
| 分项及业务类型 | 成交、推荐、负责人、交付、运营、授课等；选择适用的新报、复训或该产品支持的其他场景 |
| 发给谁 | 按订单取销售或推荐人，按成交或推荐关系取公司，或选择规则指定个人、公司、团队池。负责人跟随指定岗位时使用规则所要求的有效任职。池的归集组织与后续分配负责人另有字段 |
| 哪些业绩参与 | 整个结算周期、指定销售类别、公司、部门、小组或人员。限定来源范围与指定受益人各存独立引用。部门和小组使用组织主键及业务时点有效的归属，避免调动后回算到新部门 |
| 怎么算 | 固定额要写清单位，如每单、每报名或每期；比例要写净实收或适用计提基数；阶梯要分别写选档指标、起点、选档范围和计提范围 |
| 什么时间计入 | 固定周期取对应付款或完成窗口，实战班取实际签到期次。规则选择时间、订单归属时间、报表月份分别保留 |

同一配置界面沿用已有 Ant Design Vue 表单、人员及组织选择器、差额试算与发布入口。计算继续走已验证的 Go 计算路径。先把共同字段放到对应分项的主视图，逐步补齐缺口，每个新选项必须有实际核算、版本追溯和退款行为。保存后使用规则及订单的主键、版本引用；开放期内维护一份最新草稿。正式结算和历史扣回读取原结算版本。

产品目录显示已映射的业务 SKU。规则列表可按业务 SKU、跨 SKU 汇总或实战班报名类型筛选。实战班新报和复训可共用一期规则，筛选会保留适用于该报名类型的完整规则版本。编辑时逐块显示收款安排，展开后在同一处配置收款对象和金额。添加时先选订单上的销售、推荐人、成交公司，或指定个人、组织、团队池。一个规则可同时包含多种收款安排。现有版本中的计算方式和收款记录随原版本保留。

## 实施与验收

1. 重排现有配置和规则预览，按「发给谁」「提成怎么算」组织。显示班次来源范围、公司类别、固定额单位与选档/计提范围。验证发布入参、规则版本选择和金额保持原语义。
2. 核对实际配置导入后的可操作性。用开发库复核 499 的类别及团队拆分、创客完成时点、大使费率、健康班新报阶梯和复训拆分、家庭班总监期次归属。需要实际数据对比的结算按原行逐项核对，规则移植前先对上分、受益主体和团队池。
3. 补齐多部门及小组范围、固定账期跨产品净收款阶梯、家庭班按期归属和按期/按人固定项等已有窗口未覆盖的计算。历史归属、退款、更正回放须一并验证，避免以当前目录覆盖已确认结算。
4. 用已冻结样本校验不受新版发布影响；用开放账期校验差额、未命中或冲突提示。边界验证覆盖相邻期次、累计起点调整、任职交接、订金尾款以及按退款账期扣回。

### 财务配置操作

实战班可新增规则、复制配置到其他期次、编辑相同适用范围下的最新版本。编辑表单可新增、修改或删除分润分项。保存生成新版本，确认结算继续引用原规则。若其他配置人员先保存，重新打开最新版本后编辑。大春 AI 的费率维护支持删除可选分项和费率行，可在保存前撤销。成交分项和内部团队拆分需要保留可适用的销售费率，变更随新版生效。

有发布权限的财务人员可在规则列表指定停用时间。实战班停用所选适用范围内已发布的版本，按实际班次开始时间判断。大春 AI 停用所选规则包内的全部版本，逐单规则按付款时间判断，整期阶梯须从该规则的账期起点停用。边界之后如有其他适用规则，按原优先级选用，否则进入待核。受影响的开放账期安排试算，已确认结算继续引用原版本。

### 销售类别和公司例外

大春 AI 的分润配置先显示类别默认比例，公司单独比例和补充比例按需打开。系统从订单读取成交销售和销售公司。已有别名按付款时的有效区间解析，新账号和公司可沿用组织目录中的来源身份、公司映射和销售类别。人员需要在付款时具备该产品或项目适用的销售任职。同一类别加入新公司时，类别默认比例直接适用。公司单独比例优先。

大春 AI 可以从同产品、同类订单的现有逐单规则复制到已映射的 SKU，选择生效时间并保存成独立规则。目标已存在重叠的已生效或已排定规则时，应从目标 SKU 的配置入口维护。新增分项、修改匹配范围、内部团队收款人和规则复制通过各自的低频入口操作。

实战班的新报、复训分项按班次选择规则。成交公司分项可从组织目录选择销售类别，按各笔付款发生时的公司类别套用默认比例或固定额。启用类别匹配的规则中，识别为内部的新增公司可直接使用该报名类型的个人提成。内部公司拆分、针对单家公司的例外和指定公司范围可以单独维护。同一份报名的订金、尾款跨类别时列为待核。正式结算保留已采用的类别引用，扣回按原分润口径执行。结算后更正成交公司，原订单当时的类别引用只适用于原公司。新公司没有可核实的规则匹配时列为待核。

### 大春 AI 整期阶梯

「产品规则 → 整期阶梯」展示参与 SKU、账期和收款安排。同一规则可组合指定个人、公司和团队池。池负责人或可分配成员变动时分组。同一收款组共用选档净额，每种收款安排可设自己的档位。指定个人按所选人员和规则生效期计提，金额列入个人汇总，跨组织订单的金额未指定分摊公司或部门。团队池分别选择归集组织、负责人职责和成员职责。财务可以从同项目已映射的 SKU 中调整参与范围，仍须有相关产品的发布权限。每档从填写的起点开始，到下一档的起点之前为止，第一档从零开始。保存从新账期起点生成版本，保留原定义及此后已排定的规则版本。移除 SKU 后，新付款依新版确定是否参加，历史付款的退款继续按原付款时的规则归组。停用后可继续核算已确认账期的退款和结转。暂停的规则包可维护版本，继续保持暂停。

金额演算使用手填的场景汇总实收、本期退款和上期未抵扣退款。净额为负时计提为零，差额结转下期。净额为正时按整笔可计提净额匹配一档，乘该档比例后舍入至分。

「订单和退款核对」按规则中的场景和账期口径读取本地同步数据，分场景显示已匹配收款、退款以及原付款跨期的退款。付款按最新交易版本和付款时有效的场景映射匹配。退款按成功日期入核对期，按原付款匹配场景。重复交易、无法唯一关联原付款、累计退款超过原付款等情况进入待核。页面同时显示映射缺口和同步覆盖状态。

整期规则可在同一页面核对收退款分组。每笔交易按原付款时间匹配适用版本。团队池按池归属、有效负责人和可分配成员分段，跨期退款跟随原付款分组。成员需在原付款时同时属于对应组织并持有配置的分佣职责。缺少或冲突的规则、收款组织、负责人或成员显示为待核。每组使用自己的净额选档并展示各分项的比例、试算金额和本期未抵扣退款。「试算暂停规则」允许财务核对已发布的暂停规则，操作只读取数据。页面的试算尚未读取上期正式结转余额。

已启用的规则可打开独立的整期草稿，同一规则和月份保留一份最新草稿。整期草稿只汇总该规则的收退款与计提金额，逐单业绩只在对应的逐单账期统计。整期按原付款版本、适用规则和收款分组引用数据。上一期正式结转继承到同收款分组，空月继续结转。原退款期已确认且此前未入账的退款进入当前账期，已入账退款金额或原付款金额变化时列为待核。演算和正式汇总复用同一套档位匹配与舍入函数。

### 组织范围验收口径

班次分项可以限定销售公司、人员、多个部门或小组，以及受益人的一段任职。按部门或小组筛选来源业绩时，先从订单指定的销售角色解析人员，再按付款时点的组织归属确定所属部门和组。同一笔付款命中多个选择也只计一次。收款人的有效任职另行判断，任职开始时刻纳入、结束时刻排除。配置保存组织主键，历史退款复用结算时的实际归属。更正改变该规则所用的销售人员或公司，且缺少对应的历史归属时，进入待核。

试算样例包括旧组与新组的交接边界、同时选中部门和其下属小组、订金和尾款跨任职边界，以及不属于收款范围的复训业绩把全班推入更高一档的情况。核对档位、参与计提净额和每条实际收款金额。

### 子系统退款和按比例扣回

财务定期读取子系统成功退款。订单详情可手动重拉原订单，回显子系统已确认的退款金额及全额或部分状态。使用退款编号和原付款关联确认归属。累计成功退款等于原实收时为全额退款，小于原实收时为部分退款。退款处理中、金额或关联缺失、重复编号、累计退款超出原实收时，提示待核并从子系统更正。

采用按比例退款的分润分项按「原计提金额 × 累计成功退款 ÷ 原计提对应的付款金额」算累计应扣，四舍五入到分，再减已扣金额。同一笔付款累计全退时，扣回各分项尚未扣回的余额。原实收 1,000 元、销售计提 100 元、交付计提 10 元，退款 500 元时分别扣回 50 元、5 元。已结算的原付款使用原结算中的人员、公司、池和规则版本。扣减进入退款成功时所属账期，该账期已关账时进入当前开放账期。
