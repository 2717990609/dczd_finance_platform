# 组织与人员开发说明

原财务 A2 的「组织与人员」分内部组织、外部合作、全部人员、销售类别、职位配置和总监归属。人员详情含组织任职、业务职责、来源身份和变更记录。公司类型、销售类别、公司成员关系、职位和业务职责在代码及数据库中各有独立字段和生效规则。

| 原系统数据 | 本系统处理 |
| --- | --- |
| 销售公司档案有内部、外部或待确认类型。组织目录可关联内部销售公司 | 组织主键沿用原公司成员范围对应的组织 ID，可确认待确认的公司或调整内外部类型，保留时间和经办人。当前父级通过组织树读取 |
| 销售类别有独立名称、启停及公司分类历史 | 类别主键与公司有效区间分开保存。授权人员可维护类别，并为一家公司或同一页选择的多家公司调整类别 |
| 公司成员有负责人、管理人员、成员角色，可关联主要任职和兼任 | 沿用任职记录的人员、组织、角色和时间。导入可保留成员对应的主要任职或兼任 |
| 业务职责按组织、项目或产品配置，组长和团队负责人可同时任职 | 既有「计提任职」维护已接入的大春 AI 角色，继续按职责、范围和支付时点匹配。「业务职责」维护实战班代理推荐、资源推荐和团队总监。可登记人员或组织，并在同一范围结束或交接任职 |

组织页面使用当前组织层级。人员任职与类别历史使用各条记录的有效区间。历史结果按已保存的组织、订单及规则引用查询。销售类别按产品规则和对应业务时点参与计提。

组织数据先导入独立本机数据库，逐项核对类型、启停状态、分类历史及任职。公司目录使用分页查询，按需读取单家公司的类别历史，组织任职复用现有查询入口。


## 实战班业务职责

原财务将健康观念实战班和家庭教育实战班登记为两个产品，分别属于对应项目。组织导入保留职责记录指向的产品或项目 ID。原团队总监分项读取订单确认的最近一级总监。原任职档案将该职责登记在家庭教育实战班的组织主体，不能由档案推导健康观念实战班的收款人。

工作台可按主体、职责、范围和日期查询。从销售公司或人员任职历史也可下钻。交接按同一北京时间结束原任职并建立新任职，沿用原职责、适用范围及计划结束时间。再次导入组织快照时保留本平台已维护的任职。

业务职责供组织查询和维护。计提仍由各产品的已生效规则决定。现有大春 AI「计提任职」继续使用已有资格口径。


## 销售类别调整

调整公司类别时使用数据库保存时点。原类别在同一时点结束，新类别从该时点生效。每家公司同时核对当前类别和生效起点，遇到旧页面提交冲突时重新读取。批量操作在一个事务内完成。仍有启用公司使用的类别须先完成调整再停用，历史类别继续可查。

大春 AI 按付款时点匹配销售类别。系统通过已解析的公司主键，读取本平台生效的类别变更。变更前仍使用原有计提类别资料。实战班按各期规则区分个人和公司计提，外部公司可按付款时的组织类别自动套用标准，指定公司的约定优先。进入分润规则时重新读取可选的公司和类别。规则编辑可选择启用的类别，查看已发布规则时仍显示所引用的停用类别名称。调整完成后标记相关开放期次待试算，正式结算保留原记录。

组织快照继续补充类别历史。本平台维护的类别和变更起点保留，来源历史补充到本平台接续时点为止。


## 公司类型调整

原财务的已确认类型是内部或外部，待确认用于历史迁入。授权人员可从公司目录查询和维护类型，包括已停用的历史公司。调整复用已有公司主键，保存原类型、新类型、经办人及时间。保存时核对当前版本，重复提交相同类型沿用已有结果。

来源快照可以继续为本平台尚未维护的公司提供类型。首次在本平台维护后，后续导入保留本平台确认的类型。公司类别、成员、职责和当前上级分别使用各自的记录。按内部与外部区分计提的产品继续使用其已发布规则配置。调整公司类型会安排相关开放期次重新试算，包括实战班采用外部公司默认比例的安排。调整类别时，独立收款安排的类别比例表也会触发试算。两类调整都按各自生效时间判断订单，已确认结算保留原结果。

## A2 组织同步初始化

销售公司的组织目录 ID 取自 A2 的成员范围，业务端收到的财务公司 ID 则取自 A2 的销售公司主体。切换时须保留这两个 ID 的对应关系，以及已经分配出去的版本号。业务端已有的账号、公司和成员沿用原编号。大春 AI 健康身份还需要最近已接收的原生版本与确认状态，用于识别并发变更。

在 A2 已停止新增操作、在途投递和冲突已核清后，使用同一切换时点核对过的组织快照。先用只读 A2 PostgreSQL 连接配置运行下列命令。工具通过本地 psql 使用环境连接参数，将同步所需字段补到新的私有文件中。未完成的投递、绑定或 AI 冲突会显示数量，输出文件只在核对通过后生成。

```sh
python3 tools/export_organization_sync.py organization.json organization-with-sync.json
```

在专用开发库通过现有 `import-organization` 入口试跑。初始化新的财务库时，将补全后的快照放入初始化清单的 `organization` 字段，先运行 `initialize-finance <清单>` 核对，再按现有初始化流程执行。导入顺序为组织、人员及任职、销售类别、销售公司的两个 ID、各端绑定及版本水位、AI 类别及原生回执。导入不会投递组织消息。核对原、新系统每端绑定数量、公司源编号、最后已应用版本，以及 AI 原生变更能否接续确认。正式切换时，同一个目标端只应有一个财务系统下发变更。停用下发时保留消息和回执，以便核对接收端已经处理的版本。

家庭教育总监的旧关系从 A2 导出已核定版本 JSON，按生效期和原版本顺序在总监归属入口核定；也可以使用业务提供的六列 XLSX。资料不全的下属公司可标为待核，总监本人、本人公司和收款方需核对到唯一档案。原始文件和已生效版本可供追溯。
