# 财务平台

一期提供产品目录、来源映射、期次、规则组件、人员身份映射和来源订单查询。后端使用 Go、go-zero 和 PostgreSQL，前端使用 Vue 3、Vite 和 Ant Design Vue。

财务平台独立运行，产品、规则、组织任职、草稿和结算数据从本平台数据库读取。订单、退款、报名和签到由对应业务子系统维护，财务主动读取。正式切换后，产品与规则配置、组织任职维护、核算、结算和差额处理统一在本平台办理。

| 目录 | 内容 |
| --- | --- |
| `server/` | Go 模块、路由、数据库结构与后端测试 |
| `web/` | Vue 页面、表格与配置表单 |

规则版本保存分项、费率、适用范围及来源角色。订单修订各保存一次，试算明细引用订单、人员归属和规则版本。

本地工作台可配置自然月和 25–24 等固定账期，试算销售及推荐提成，查看唯一最新草稿和待核项。固定账期按上海时间划分，人员归属按实际付款时点读取。同一核算范围、规则和财务结果重复试算时沿用当前草稿。「业绩与分润」按当前草稿或已确认版本查看人员、公司和部门汇总。订单业绩按订单发生时的销售归属统计，分润按受益人归属统计，退款按原付款归属冲减。未能唯一匹配的归属显示为「归属待核」。

固定账期按付款时点选规则版本，实际开班按子系统确认名单中的开班时点选整期规则。指定期次优先于起始期数，起始期数优先于产品默认。固定账期内不同付款可以匹配不同版本，实际开班一期共用一个规则版本。

实战班试算关联来源期次标识，由已确认签到的最新名单决定纳入哪些报名。新报、复训可配置不同销售或推荐分项。订金和尾款按一份报名计算，再按原付款金额分摊分润。仅签到的赠送或兑换报名计入到课人数。延期后，以原期和目标期各自的最新确认名单重算。若两期同时留有同一份符合计提条件的报名，试算列为待核。实战班的新报个人销售支持累计人数、本期实付和人数优先三种阶梯。累计可以从期数或开班时间起算。可在同一规则版本内为个人单独设置起点，切点到达后重算该人员的累计。档位可配置上下限、比例或固定额。可以按来源订单中的销售公司配置不同档位。同一人的累计人数与选档业绩合并统计，销售公司选项从数据库的 `practiceSalesCompany` 配置读取。累计按原付款时点归属的人员主键分组；历史名单、付款和归属有缺漏时显示待核。公司和负责人分润、交付分配、退款及正式结算仍待完整实现。

固定账期试算支持成功退款的扣回。分项按计提时使用的规则选择按比例扣回、整笔冲回或不扣回。同账期退款在本期抵扣，历史退款在退款归属期仍开放时进入该期，关账后由当前办理期承接。明细同时显示原受益人、原结算期、退款归属期及实际扣减期。缺少原付款关系、规则口径或已入账退款发生变更时，系统列入待核。

已结算订单的推荐分项按结算时使用的规则版本，根据最新订单版本试算差额。更正比较原入账、后续已入账差额及退款，原结算固定。扣回处理尚未核实时显示待核，确认原受益人离职且无法联系的场景保留正确人员的补发。正式登记扣回处理仍需接入获授权的财务办理入口。

结算确认的事务和数据库约束可通过集成测试验证。产品默认关闭确认，开发工作台可查已确认结果。正式办理入口待完成财务权限配置及产品对账后开放。

## 本地运行

需要 Go 1.25、Node.js 22、pnpm 10 和专用 PostgreSQL 开发库。首次配置时将 `.env.example` 复制为 `.env.local`，填写本地开发库连接。库名须以 `_dev` 结尾，并与 `FINANCE_EXPECTED_DATABASE` 一致。服务启动时初始化一期表。此配置文件仅保存在本机。

```sh
test -e .env.local || cp .env.example .env.local
chmod 600 .env.local
```

填写后，在仓库根目录启动。

```sh
set -a
. ./.env.local
set +a
go -C server run .
```

在另一个终端启动前端。

```sh
pnpm --dir web install
pnpm --dir web dev
```

前端地址为 `http://127.0.0.1:5176/`，开发代理转发至后端 `127.0.0.1:8096`。`/healthz` 检查 HTTP 服务，`/readyz` 检查开发库连接。

工作台的固定下拉选项由数据库 `configuration_options` 提供，可配置显示名、顺序、是否启用和适用范围。应用从 `GET /api/v1/configuration-options` 读取，初始化仅补入缺少的默认项，不覆盖已有配置。产品、人员和期次从各自的业务表读取。选项编码对应服务端支持的业务行为，改显示名或排列不会修改已经保存的规则。

工作台的「组织与人员」从本平台数据库查询。可按公司、部门、小组或门店筛选直接任职，查看当前归属、指定日期北京时间零点的归属，或全部任职记录。任职起止按区间保存，结束时刻与下一段起始时刻重合时，由新任职生效。组织树显示当前层级，已停用组织仍可查询任职历史。组织和任职的授权维护入口待接入。

技术人员可在专用开发库一次性导入组织数据。文件包含 `capturedAt`、`people`、`units` 和 `assignments`。人员使用 `id` 和 `name`，组织使用 `id`、`parentId`、`name`、`kind`、`status` 及可选的 `sortOrder`，任职使用 `id`、`personId`、`unitId`、`kind`、`position`、`from` 和可空的 `to`。可选的 `companies` 用 `source`、`sourceCompanyId`、`companyId`、`from` 和可空的 `to` 保存来源销售公司标识的有效区间。相同的人员主键与已有人员档案共用，全部记录在单个事务中写入。

```sh
go -C server run . import-organization /path/to/organization.json
```

技术人员可以一次性将核验过的产品与规则配置文件导入专用开发库。产品进入产品目录，规则进入统一的规则列表，保留其作用域、版本、有效期和暂停状态。完成核算实现和金额验证前，相关产品的规则显示为待启用。

```sh
go -C server run . import-product-config /path/to/product-config.json
```

固定账期配置包含场景映射时，试算页的「订单规则匹配」按实际付款时间查看来源场景及规则版本。同优先级规则重叠时列为冲突。大春 AI 499 的「查看销售分项」根据成交时有效的来源人员、销售公司、费率类别、销售任职和小组归属计算。符合内部拆分条件时，各岗位金额合计与销售总额一致。缺少归属或任职时显示具体待核原因。展示的分项用于核对，正式计提待整套规则与实际业务验证后开放。

「查看负责人、公司与团队池」按付款时的有效任职计算负责人分项，直接归公司的分项使用规则指定的公司。团队池先按付款逐笔归集，分配负责人通过付款时点的任职确定。工作台的「团队池归集」显示完整账期的付款笔数、归集金额和待核笔数。月度分配、退款扣减及正式结算待接入。

可将销售及收益归属资料通过 `import-sales-context` 导入专用开发库。文件包含 `source`、`capturedAt`、`people`、`personLinks`、`companyLinks`、`categories` 和 `appointments`，其中人员链接使用已合并的正式人员主键，类别与任职保留起止时间。公司链接的 `unitId` 对应已导入的公司组织主键。启用公司与团队池核算时，文件还需要 `organizations` 数组，以 `partyId` 和 `unitId` 关联规则指向的组织主体与本平台组织。

开发验证可使用测试来源接口选取样本。可将 `source` 和 `facts` 写入同一个 JSON 文件，`facts` 为来源接口返回的 `source.order-fact/1.0` 记录数组。在专用开发库可重复导入同一文件。已配置单笔接口的环境可按原订单 ID 查看来源更新。

```sh
go -C server run . import-order-facts /path/to/source-order-facts.json
```

需要验证实战班时，技术人员可以从子系统一次性取得已确认的 `dczd.practice-roster/1.0` 名单，使用已加载的本地环境配置导入。该命令只接收专用开发库，重复导入同一版本会核对内容并复用原记录。然后在「核算期次」填写名单的来源期次标识，配置规则和对应的来源产品映射，在「分润试算」查看结果。原付款仍需作为来源订单事实入库才能计提。

```sh
go -C server run . import-practice-roster /path/to/roster.json
```

已有关账历史的实战班可以导入冻结的个人累计期初。在专用开发库导入 JSON 后，在实战班新报阶梯的默认累计起点选择相应批次。文件使用 `productId`、冻结结算的 `sourceSettlementId`、`throughAt` 和 `people`。每个 `people` 项带财务人员识别键 `legacyPartyId` 和 `newCount`。首次建立本地人员引用时填入来源的 `displayName`，已有同主键人员可省略。同一个结算的相同内容重复导入会复用批次。

```sh
go -C server run . import-practice-count-opening /path/to/opening.json
```

选用冻结期初后，只将截止时刻之后的已确认新报追加到期初。生效的个人起点按个人窗口重新累计。明确的零期初保留为零，缺少期初记录时显示待核。

```sh
curl --fail http://127.0.0.1:8096/healthz
curl --fail http://127.0.0.1:8096/readyz
go -C server test ./...
pnpm --dir web build
```

指定 `FINANCE_TEST_DATABASE_URL` 可运行 PostgreSQL 集成测试。请使用名称以 `_dev` 结尾的独立测试数据库和有权创建临时测试 schema 的账号。测试会在对应 schema 内创建和验证数据，随后清理该 schema。
