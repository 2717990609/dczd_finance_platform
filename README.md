# 财务平台

财务工作台提供产品目录、来源映射、期次、产品规则、组织人员、来源订单、分润试算和结算核对。后端使用 Go、go-zero 和 PostgreSQL，前端使用 Vue 3、Vite 和 Ant Design Vue。

财务平台拥有独立的应用和数据库。正式切换后，本平台是财务业务的唯一办理入口。产品规则、组织任职、账号权限、核算、结算和差额处理均在本平台维护。订单、退款、报名和签到由对应业务子系统维护，财务主动读取。

工作台统一使用「产品规则」「适用规则」「计提时规则」「结算时规则」。规则配置文件用于上线初始化。日常核算从本平台数据库选用规则版本，授权配置人员在本平台保存并生效。历史结算通过已保存的版本引用查询当时实际使用的规则。

| 目录 | 内容 |
| --- | --- |
| `server/` | Go 模块、路由、数据库结构与后端测试 |
| `web/` | Vue 页面、表格与配置表单 |

## 正式切换验收

- 正式用到的产品、场景、规则版本、组织任职、财务账号和历史衔接数据完成初始化及核对。核对实战班累计期初、团队池余额和待处理差额。使用独立的应用配置，仅连接本平台数据库和所需业务子系统，验证完整办理流程。
- 使用本平台账号验证授权配置人员可在工作台保存并生效产品规则。以产品和账期试跑，核对订单与期次匹配、人员归属、计提、退款、差额和分配金额。
- 在本平台完成试算、正式结算及历史查询。确认后的结果通过订单、规则和任职引用核对；后续发现来源错误，由业务子系统更正并主动重拉。切换后的同一产品账期由本平台办理。

## 核算与报表

规则版本保存分项、费率、适用范围及来源角色。订单修订各保存一次，试算明细引用订单、人员归属和规则版本。

本地工作台可配置自然月和 25–24 等固定账期，试算销售及推荐提成，查看唯一最新草稿和待核项。固定账期按上海时间划分，人员归属按实际付款时点读取。同一核算范围、规则和财务结果重复试算时沿用当前草稿。「业绩与分润」按当前草稿或已确认版本查看人员、公司和部门汇总。订单业绩按订单发生时的销售归属统计，分润按受益人归属统计，退款按原付款归属冲减。未能唯一匹配的归属显示为「归属待核」。

订单核算字段、规则、人员归属或签到名单有变化时，系统标记受影响的开放期次。自动试算默认每 30 分钟扫描一次，更新同一份草稿且跳过未标记的期次。订单展示信息变化只保存订单版本。工作台显示待试算状态，也可手动重新试算。已确认的结算使用保存时的结果及规则版本。开发环境可通过 `FINANCE_DRAFT_REFRESH_INTERVAL` 调整扫描间隔，设为 `0` 时只执行手动试算。

固定账期按付款时点选规则版本，实际开班按子系统确认名单中的开班时点选整期规则。指定期次优先于起始期数，起始期数优先于产品默认。固定账期内不同付款可以匹配不同版本，实际开班一期共用一个规则版本。

实战班试算关联来源期次标识，由已确认签到的最新名单决定纳入哪些报名。新报、复训可配置不同销售或推荐分项。订金和尾款按一份报名计算，个人销售和推荐按净实收分摊。仅签到的赠送或兑换报名计入到课人数。延期后，以原期和目标期各自的最新确认名单重算。若同一付款仍在两份有效名单中，两个期次都列为待核。实战班的新报个人销售支持累计人数、本期实付和人数优先三种阶梯。累计可以从期数或开班时间起算。可在同一规则版本内为个人单独设置起点，切点到达后重算该人员的累计。档位可配置上下限、比例或固定额。可以按来源订单中的销售公司配置不同档位。同一人的累计人数与选档业绩合并统计，销售公司选项从数据库的 `practiceSalesCompany` 配置读取。累计按原付款时点归属的人员主键分组。历史名单、付款和归属有缺漏时显示待核。

负责人和交付分项支持按班次净实收计提，可命名并指定收款人员或组织。适用范围可按新报、复训、销售公司或销售人员限定。需要跟随任职的分项可选择任职组织和方式，只计入任职生效后、结束前的付款。交付阶梯支持用全班净实收选档，再按适用报名的净实收计提。班次计提总额按分舍入，再将尾差分配到报名。订金和尾款按原实付拆分该报名的份额。人员、公司、部门视角可核对同一份草稿。

「外部销售公司提成」适用于直接向公司计提的分项。新报按报名净实收的比例计算，复训可以选比例或每份报名固定额。同一类别的公司共享标准，可单独覆盖某公司的比例或金额。外部公司由实际付款时的公司映射确定收款主体，业绩仍按实际销售人员归属。启用外部公司分项后，同时选择适用个人销售规则的内部公司，未明确配置或映射不唯一的付款列入待核。个人阶梯排除为公司计提的报名，跨期累计使用各班次适用的销售角色和公司规则。

外部公司新报可另设公司推荐比例，并从公司目录选择本版规则可直接收取推荐分润的公司。系统优先使用订单指定的推荐公司，未指定时读取目录当前登记的公司推荐关系。已登记无推荐关系时按零处理，关系缺失、缺少适用的直收配置、收款公司停用或订金与尾款归属不一致时提示待核。推荐分润按一份报名的净实收舍入，按原实付款拆至订金和尾款，并在试算中单列推荐公司的收款。

实战班的复训固定销售提成可按公司拆分。填写销售份额和可选的服务人员份额，余额归入指定资金池。确认名单前发生部分退款且报名仍有效时，保留该公司的固定拆分。拆分按报名计算，并保持订金和尾款各自的应计金额。班次净实收的服务、交付等分项也可归入同一资金池。资金池绑定产品和归集组织，规则引用资金池及分配负责人。财务可在「团队池分配」给原付款时属于归集组织的成员分配，也可登记组织留存。公司、部门和人员汇总读取同一份草稿及其有效分配，合计不因分配而变化。

实战班开放草稿使用最新确认名单。确认前已成功且能唯一匹配原付款的部分退款冲减试算业绩，比例分润及实付阶梯按净实收计算，仍有效的报名按一人计。固定分项可配置退款处理方式，新报固定销售提成遇到部分退款时须有明确配置。已全退的付款仍在确认名单中时提示核对名单。首次确认后的退款在开放班次单独提示。

实战班可按产品登记独立的「退款账期」，当月没有开班也可建立。默认按 25–24 划分，产品可配置开始日。原班次已经确认后，新增退款进退款成功日所属的开放月份。归属月已关账时，进入当前办理月，或沿用此前仍开放的办理月。补同步到的退款如果发生在名单确认前，也按原班次是否已处理判断，防止遗漏或重复。独立计提按结算时使用的规则版本逐笔试算扣减。订金和尾款联动、销售阶梯和班次分润按已结算班次复算，将同一归属月的退款合并处理。试算使用当时的名单、付款、规则和人员归属，结合之前已入账的退款，只扣本次新增差额。明细显示受益人、班次结算期、退款归属期及实际扣减期。账期缺失、已入账退款的关键字段变化或班次结算无法复现时列为待核。实战班正式结算及跨账期资金池余额仍待上线验证。

固定账期试算支持成功退款的扣回。分项按计提时使用的规则选择按比例扣回、整笔冲回或不扣回。同账期退款在本期抵扣，历史退款在退款归属期仍开放时进入该期，关账后由当前办理期承接。明细同时显示原受益人、原结算期、退款归属期及实际扣减期。缺少原付款关系、规则口径或已入账退款发生变更时，系统列入待核。

已结算订单的推荐分项按结算时使用的规则版本，根据最新订单版本试算差额。更正比较原入账、后续已入账差额及退款，原结算固定。扣回处理尚未核实时显示待核，确认原受益人离职且无法联系的场景保留正确人员的补发。正式登记扣回处理仍需接入获授权的财务办理入口。

大春 AI 499 支持在工作台确认结算。产品默认关闭确认，按实际对账结果启用。确认后的账期保留一份正式结果，工作台可查其明细和分配结果。

## 本地运行

需要 Go 1.25、Node.js 22、pnpm 10 和专用 PostgreSQL 开发库。首次配置时将 `.env.example` 复制为 `.env.local`，填写本地开发库连接。开发模式使用回环地址和以 `_dev` 结尾的数据库。库名须与 `FINANCE_EXPECTED_DATABASE` 一致。服务启动时初始化表。此配置文件仅保存在本机。

```sh
test -e .env.local || cp .env.example .env.local
chmod 600 .env.local
```

填写后，在仓库根目录启动。

```sh
set -a
. ./.env.local
set +a
go -C server run .
```

在另一个终端启动前端。

```sh
pnpm --dir web install
pnpm --dir web dev
```

前端地址为 `http://127.0.0.1:5176/`，开发代理转发至后端 `127.0.0.1:8096`。`/healthz` 检查 HTTP 服务，`/readyz` 检查开发库连接。

## 财务账号

默认的 `FINANCE_ACCESS_MODE=managed` 要求登录后使用工作台。后端监听回环地址，对外访问由同源 HTTPS 代理转发。仅本机开发库可设为 `development` 来匿名读取和试算开发样本。

账号关联已有的财务人员主键。技术人员使用 `configure-finance-account` 登记账号或调整权限。配置文件可参照下例，人员和产品 ID 使用本平台实际主键。

```json
{
  "login": "finance.operator",
  "personId": 1,
  "enabled": true,
  "workspace": true,
  "rules": [{ "productId": 1, "publish": true }],
  "settlements": [1]
}
```

首次登记或更换密码时，通过标准输入将密码传给 `go -C server run . configure-finance-account /path/to/account.json`。密码使用安全的凭据输入渠道。调整权限或停用时可用 `</dev/null` 保留密码。修改后的配置替换该账号的权限并使既有会话失效。

`workspace: true` 授予全量业务工作台访问，包括全量订单、试算和报表。规则定义的读取和规则发布均按 `rules` 的产品授权校验。`publish: false` 可以查看该产品的规则。发布记录使用当前登录账号主键。从工作台退出会撤销本次会话。

`settlements` 列出该账号可以确认结算的产品主键，需同时具有工作台权限。结算前按当前登录账号重新校验该账期的产品权限。

## 产品与数据配置

工作台的固定下拉选项由数据库 `configuration_options` 提供，可配置显示名、顺序、是否启用和适用范围。应用从 `GET /api/v1/configuration-options` 读取，初始化仅补入缺少的默认项，不覆盖已有配置。产品、人员和期次从各自的业务表读取。选项编码对应服务端支持的业务行为，改显示名或排列不会修改已经保存的规则。

工作台的「组织与人员」从本平台数据库查询。可按公司、部门、小组或门店筛选直接任职，查看当前归属、指定日期北京时间零点的归属，或全部任职记录。任职起止按区间保存，结束时刻与下一段起始时刻重合时，由新任职生效。组织树显示当前层级，已停用组织仍可查询任职历史。组织和任职的授权维护入口待接入。

技术人员可在专用开发库一次性导入组织数据。文件包含 `capturedAt`、`people`、`units` 和 `assignments`。人员使用 `id` 和 `name`，组织使用 `id`、`parentId`、`name`、`kind`、`status` 及可选的 `sortOrder`，任职使用 `id`、`personId`、`unitId`、`kind`、`position`、`from` 和可空的 `to`。可选的 `companies` 用 `source`、`sourceCompanyId`、`companyId`、`from` 和可空的 `to` 保存来源销售公司标识的有效区间。相同的人员主键与已有人员档案共用，全部记录在单个事务中写入。

可选的 `recommendations` 使用 `companyId`、`referrerCompanyId` 两个公司主键登记已核对的公司推荐关系。明确无推荐关系时填 `"referrerCompanyId": null`。目录变更会标记相关开放草稿重新试算。

```sh
go -C server run . import-organization /path/to/organization.json
```

技术人员可以用核验过的配置文件初始化专用开发库的产品和规则。产品进入产品目录，规则进入「产品规则」，包含适用范围、版本、有效期和暂停状态。日常规则维护使用本平台的授权配置入口。完成核算实现和金额验证前，相关产品的规则显示为待启用。

```sh
go -C server run . import-product-config /path/to/product-config.json
```

固定账期配置包含场景映射时，试算页的「订单规则匹配」按实际付款时间查看业务场景及适用规则。同优先级规则重叠时列为冲突。大春 AI 499 的「查看销售分项」根据成交时有效的来源人员、销售公司、费率类别、销售任职和小组归属计算。符合内部拆分条件时，各岗位金额合计与销售总额一致。缺少归属或任职时显示具体待核原因。正式结果在「结算核对」确认后生成。

大春 AI 499 的「产品规则 → 分润费率」按分项展示固定比例和费率表，可按销售公司、关系或类别筛选。具备该产品发布权限时，可修改比例并指定北京时间的生效时点。每次金额参数实际变化生成一版规则，记录发布账号，并仅标记采用新版规则的开放账期。订单按付款时点选版，历史结算和其后的退款继续引用原结算的规则。与内部团队拆分联动的销售总费率由拆分规则约束。

工作台使用财务账号会话访问费率配置接口。技术集成可显式配置受信任的签发方，通过 Bearer 调用同一接口。使用 `FINANCE_SESSION_ISSUER`、`FINANCE_SESSION_SECRET` 校验签发，Token 需包含匹配的 `iss`、`aud=finance-platform`、有效的 `exp`、账号主键 `sub`、授权产品 `product_ids` 和 `permission_codes`。可读权限为 `finance.rules.read`，发布权限为 `finance.rules.publish`。

大春 AI 499 可在「分润试算」生成付款与退款草稿。每期只保留一份草稿，明细引用订单版本和适用规则版本。按付款时的有效任职计算负责人分项，公司分润归规则指定的公司，团队池逐笔归集。公司、部门和人员都能查看同一草稿的净业绩、计提和退款扣减，人员视角单列公司及团队池分润。实时匹配页的「团队池归集」显示整个账期的付款归集金额和待核笔数。

会员退款按业务子系统的退款成功日归期，从原付款计提行读取实际费率和受益对象。内部销售按整组剩余金额分配各岗位扣回，并保留各岗位的累计上限。退款扣减明细可回查原结算期、退款归属期和实际扣减期。已入账退款的关键字段发生变化时进入待核。已有只含付款计提的会员草稿会提示重新试算。

试算的「团队池分配」按池显示期初、归集、退款和余额。可从付款时具备成员资格的人员中选择分配对象，输入成员金额或组织留存金额。保存会校验各成员可用的款项并关联到来源计提行。「业绩与分润」显示拟分配金额，汇总总额不变。试算、资格资料或前期结算变化后，原填金额可以复核，过期方案暂停计入汇总。已确认到人的分配发生退款时，扣减回原团队池，池余额不足时由后续归集弥补。

大春 AI 499 的「结算核对」显示账期状态、来源同步、待核项和各池剩余待分配金额。正余额在确认前完成成员分配或组织留存，负余额由后续归集抵扣。产品完成对账后可启用 `settlement_enabled`。授权财务在确认弹窗核对产品、账期、草稿版本和合计金额。结算事务再次校验最新试算、分配版本及来源覆盖和时效，确认后保留当期付款、退款、分配及规则版本。同一版本与分配重复提交会返回已有的结算。调整早期结算前须检查同一团队池的后续已结算账期。正式切换的团队池期初余额仍需交接核对。

可将销售及收益归属资料通过 `import-sales-context` 导入专用开发库。文件包含 `source`、`capturedAt`、`people`、`personLinks`、`companyLinks`、`categories` 和 `appointments`，其中人员链接使用已合并的正式人员主键，类别与任职保留起止时间。公司链接的 `unitId` 对应已导入的公司组织主键。可选的 `categoryOptions` 用 `id`、`name` 和 `sortOrder` 初始化费率表类别选项。启用公司与团队池核算时，文件还需要 `organizations` 数组，以 `partyId` 和 `unitId` 关联规则指向的组织主体与本平台组织。

开发验证可使用测试来源接口选取样本。可将 `source` 和 `facts` 写入同一个 JSON 文件，`facts` 为来源接口返回的 `source.order-fact/1.0` 记录数组。在专用开发库可重复导入同一文件。已配置单笔接口的环境可按原订单 ID 查看来源更新。

```sh
go -C server run . import-order-facts /path/to/source-order-facts.json
```

专用开发库可直接读取大春 AI 的会员和健康身份订单流。配置来源地址及服务凭证后，在「来源订单」的「订单同步」中选择对应订单流。首次填写需要覆盖的历史起点，页面会显示排队、读取进度及同步结果。技术命令可触发同一任务。

```sh
go -C server run . sync-dcai-orders VIP_ORDERS 2026-07-25T00:00:00+08:00
go -C server run . sync-dcai-orders HEALTH_IDENTITY_ORDERS 2026-07-25T00:00:00+08:00
```

后续执行可省略日期，继续未完成的水位，或从已完成水位回看 24 小时后同步。已完成的流可以指定更早日期补历史。同一订单流的同步请求共用当前任务和检查点。末页事实、完成水位及任务成功状态在同一事务提交，服务重启后会继续未完成任务。单笔重拉更新该订单和来源状态。结算核对同时检查账期覆盖和同步进度。

已初始化的流按 `FINANCE_DCAI_SYNC_INTERVAL` 自动同步，默认 `30m`。设置为 `0` 可关闭自动触发，手动任务仍可运行。首次接入使用尚未导入大春 AI 样本的专用库。分页和单笔重拉使用同一配置来源，开发样本文件可在单独的样本库导入。结算核对要求同步水位覆盖账期，并使用 `FINANCE_SETTLEMENT_SYNC_MAX_AGE` 检查来源水位与最近一次成功同步时间。默认取一小时与自动同步间隔中的较大值。

大春之道通过同一「订单同步」入口读取订单与退款。设置 `FINANCE_DCZD_URL` 和 `FINANCE_DCZD_TOKEN`，选「大春之道订单与退款」并填写历史起点。首次同步按来源事实进入读取接口的时间取数，订单的付款和退款发生时间按原始数据保存。系统校验来源就绪状态与冲突数，按来源分页上限读取，中断后从已保存的位置续拉。分页与单笔重拉绑定同一来源，首次接入使用尚未导入大春之道样本的库。已初始化的订单流可以通过 `FINANCE_DCZD_SYNC_INTERVAL` 定时同步，默认 `30m`，设为 `0` 时保留手动同步。

```sh
go -C server run . sync-dczd-orders ORDER_FACTS 2026-07-01T00:00:00+08:00
```

需要验证实战班时，技术人员可以从子系统一次性取得已确认的 `dczd.practice-roster/1.0` 名单，使用已加载的本地环境配置导入。该命令只接收专用开发库，重复导入同一版本会核对内容并复用原记录。然后在「核算期次」填写名单的来源期次标识，配置规则和对应的来源产品映射，在「分润试算」查看结果。原付款仍需作为来源订单事实入库才能计提。

```sh
go -C server run . import-practice-roster /path/to/roster.json
```

已有关账历史的实战班可以导入冻结的个人累计期初。在专用开发库导入 JSON 后，在实战班新报阶梯的默认累计起点选择相应批次。文件使用 `productId`、冻结结算的 `sourceSettlementId`、`throughAt` 和 `people`。每个 `people` 项带财务人员识别键 `legacyPartyId` 和 `newCount`。首次建立本地人员引用时填入来源的 `displayName`，已有同主键人员可省略。同一个结算的相同内容重复导入会复用批次。

```sh
go -C server run . import-practice-count-opening /path/to/opening.json
```
